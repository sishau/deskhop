# DeskHop 屏幕布局方案 — 现行设计：v4 统一符号平面 + 虚拟通道

演进线：v2 副显门户（2026-09-29，已上板 2.80）→ v3 主屏门户（v0.80.4=904）→ v3.1 漂移修复（905）→ **v4 平面模型（v0.80.6=906，现行）** → k 标定（909）→ 版本重置 **v0.80.1 = 801**（产物 `build/deskhop-v0801-plane.uf2`，待刷板）。
历史设计细节见 git（commits 594fe2f / 7eac73e / 7f8a4fc），本文只保留现行设计与仍有效的结论。

## 1. 现场条件与硬约束

```
┌─────────┬─────────┐
│ 副显    │ 主显    │   副显经 HDMI/DP KVM 盒（按钮）在两机间切换
├─────────┤         │   本机 = Output A（主显+副显）；笔记本 = Output B（内屏+副显）
│ 内屏    │ (空档)  │   三屏全 1920×1080
└─────────┴─────────┘
```

- **KB5003637**：Windows 把 HID 绝对坐标钳制到"Windows 主显示器"→ 副显只能走相对模式接口（index>1）。**绝对=命令 / 相对=建议**：绝对报告 OS 直接放置（k 不生效）；相对报告过 OS 指针倍率 k 变换。
- KVM 按钮只动视频路径，Pico 可观测世界逐比特不变；HID 单向无回读 → **副显归属那 1 比特不在任何可观测量中**（信息论封口）→ 布局切换须手动热键，纯固件自适应不可行。
- 预算：可执行区 188KB 软限制，真实余量看 `.pad`（当前 ~112KB）；RAM ~59%。无需任何裁剪。

## 2. 方案演进摘要（为什么走到 v4）

| 代 | 核心设计 | 结局 |
|---|---|---|
| v2 副显门户 | 副显=index1 绝对、当 Windows 主显；Profile 1 垂直边界 / Profile 2 水平边界 | 已上板（2.80）。副显消失=Windows 主显消失 → **桌面图标每次 KVM 切换重排**（结构性根因） |
| v3 主屏门户 | 反转：主屏（内屏/主显）恒 index1 绝对永不消失，副显恒 index2 相对 → 图标根治 | 实测两大问题：相对屏账本按 move×speed×加速度累加而报告原始透传（最多 4× 膨胀）→ 漂移；落点按比例映射依赖 OS 倍率 1:1 → 漂忽 |
| v3.1 | 相对屏改 `move×32767÷side_px` 带余数精确累加；跨机落点改确定性角落 | 副屏往返干净了，但 OS 倍率≠1（笔记本 k=1.5）时精确累加仍失效；高 DPI 鼠标+固件加速度单包巨量增量"瞬移过边" |
| **v4 平面** | 符号平面 + 虚拟通道（下文 §3）+ k 标定（§4） | 现行 |

v4 的两条稳定性修复沿袭自 v3.1 实测：**OFFSET_CAP=4096**（~1/8 屏，单报告增量钳制，治瞬移过边）；自然交接边**零 threshold 间隙**（加间隙=固件滞后光标 ~30px，v0.80.7=907 修复）。

## 3. v4 平面模型（现行设计）

### 3.1 平面定义（mouse.c）

原点 = 主显左上角，y 向下（HID 惯例）；x ∈ [−32767, +32767]，y ∈ [0, 65535]：

```
   side display      |  main display       y ∈ [0, 32767]
   internal screen   |  virtual corridor   y ∈ [32768, 65535]
                     x = 0
```

- **主显 / 内屏** = 两机 Windows primary，绝对报告 1:1 驱动，零漂移零校准
- **副显** = 相对（KB5003637 硬约束），精确累加跟踪（§4）
- **虚拟通道** = 无输出；光标隐藏，平面坐标继续行走——内屏↔主显对角路径按真实轨迹走，落点比例对应
- `plane_x/plane_y`（int32，device_t）唯一真源；`pointer_x/y`（int16，协议字段 1/2）镜像当前 cell 屏幕局部坐标（**仅绝对报告更新镜像**——相对报告的 x/y 是增量，写入会污染）

### 3.2 边类型（按 profile）

| 边 | P1 (side=A) | P2 (side=B) |
|---|---|---|
| 主显左缘 ↔ 副显右缘 | 同机**自然交接**（零门槛，模式翻转即可） | 跨机：左出 = **停泊+精确脉冲**；右出 = 直切（绝对落点） |
| 副显下缘 ↔ 内屏上缘 | 下出 = 直切；上入 = 停泊+精确脉冲 | 同机**自然交接** |
| 主显下缘 ↔ 通道 / 内屏右缘 ↔ 通道 | **通道**（进出均吃 jump_threshold + 拖拽禁切） | 同 |
| 主显右/上缘、副显左/上缘、内屏左/下缘、通道右/下缘 | 物理墙（钳制） | 同 |

- **自然交接**：OS 光标已物理跨界，固件只翻转坐标模式 + 重锚平面，零报告零落点计算。
- **直切出副显**：Windows 已把光标钳在副显出门缘（host 拓扑中该边外无屏），移动报告即停泊；目标 = primary，绝对放置比例精确。
- **停泊+精确脉冲入副显**（**无需跨 Pico 通讯**——鼠标板单点持有全部状态）：目标机器 primary 上绝对停泊（P1 主显左下角 / P2 内屏右上角，用户固化偏好：进主显=左下角、进内屏=左上角）→ 单包相对脉冲（16-bit ±32767 单包毫秒级），尺寸按 exit 坐标与 side_px 精确算出；落点悬停共享边上方 **8px 边距**（免疫 3px 级排列偏差，v0.80.8=908）。
- **通道**：进入 = 停泊在出门缘（移动报告自动完成）+ 隐藏；退出 = 比例精确落点（两端皆 primary）。

### 3.3 稳定性机制

1. OFFSET_CAP=4096 单报告钳制；2. 交叉检测支持双轴同时越界（按参数 t 取先到者+插值）；3. 拖拽禁所有门槛类切换（自然交接允许）；4. 相对余数在模式翻转时清零；`create_mouse_report` 对 SIDE cell 强制相对（防 profile 翻转瞬间绝对越界报告）。
5. **跨端点顺序保证（2026-10-10 实测修复）**：park（绝对/ITF0）与 pulse（相对/ITF1）走**不同中断端点**，端点 ready ≠ 主机已消费前包，两端点同帧轮询 → 相对脉冲可越过绝对停泊先到，光标停在停泊点（P2 主显左缘→副显"落到内屏右上角"的根因；P1 经 UART 单 FIFO 天然保序故未暴露）。修复：任一绝对报告提交后开启 `REL_HOLD_TICKS=10`（5ms @2kHz）结算窗（device_t.abs_settle），期间相对报告缓发；仅模式翻转瞬间生效，无可感代价。

## 4. 指针倍率标定 k（config v10）

笔记本实测 k=1.5000（滑块非 1:1 档、EPP 关）证明：滑块位置不必固定，**常数 k 可被固件除掉**。主机 k=1.0000。

- **存储**：config v10 新增 `pointer_k_pm`（千分比，1000=1:1，API 字段 87），默认 1000；刷 v10 后配置重置一次（重设 Threshold/Speed 即可，side_px 默认 1920×1080 即现役硬件）。
- **同步**：心跳包 `data16[1]`（原空闲）搭载本机 k → 对端 `peer_k_pm`（RAM）；0 = 对端旧固件按 1:1。无新消息类型、无启动竞争，≤1 心跳周期收敛。
- **账本**：副显上 `plane += counts × k × 32767 ÷ side_px`（int64，余数域有界）——任意常数 k 下账本与真实光标逐像素同步。
- **脉冲**：落点先按 px 计算（含 8px 边距），再 `counts = px × 1000 ÷ k`——任意 k 下落点精确（截断误差 ≤1.5px，被边距吸收）。
- **k 的选择**：渲染副显报告的机器 = 副显主人（P1=A / P2=B）；数学在鼠标板，按 `board_role` 取 own / peer k。
- **硬前提不变**：两机 EPP 必须关（k 必须常数）；滑块位置从此无关。

## 5. 版本与刷板

- **版本编码**：`u16 = major*1000 + minor*10 + patch`（2026-10-10 起去掉旧 +100 偏移），现行 **v0.80.1 = 801**。心跳版本比较 `other > mine` 触发反向拉取升级。
- **刷 801 流程（版本倒挂红线）**：板上仍是 90x 的话，**两板断电、逐板 BOOTSEL 刷**，任何一块 90x 板活着会把 801 板反向覆盖。
- **刷后**：config v10 重置 → 重设 Jump Threshold / Speed X/Y → 笔记本板（OUTPUT_B）webconfig API 字段 **87 = 1500**（主机板保持 1000，**必做**——k 不符时脉冲深度 1.5× 失准、副显账本全程 1.5× 比例偏差）→ 两机 EPP 确认关闭 → 六门户复测（P1 副显往返 / 内屏上缘→副显脉冲 / P2 主显左缘→副显脉冲）。
- **构建教训（2026-10-10）**：disk.img / CMakeLists.txt 等仓库根文件**不在 src/ 增量推送范围**，且 CMake 不把 disk.img 声明为依赖 → 增量推送 + 普通重编会**嵌入陈旧 config 页面**（板页显示 v0.70.1 = 新编码 801 被旧 −100 反解）。改网页或根文件后必须**整仓推送 + `--clean-first` 重编**，并解剖 UF2 验证嵌入页（提取 disk 区 atob blob 解压看反解）与 metadata 版本。
- 刷后若副屏路径仍异常：下一嫌疑 = 鼠标厂商驱动（G Hub/Synapse）在 OS 之下动指针。

## 7. 已知取舍与存档

- 切 profile（Ctrl+M）瞬间光标在副显上：归属翻转，建议先移回主显/内屏；`create` 的防御性相对避免越界报告。
- 通道内滚轮/按键丢弃（光标不可见）。
- 虚拟桌面（screen_index）机制被平面取代；webconfig Screen Count 字段失效；macOS workaround 已移除（纯 Windows 环境）。
- **历史探讨存档**（详细论证见 git 历史 / 旧版文档）：
  - 全相对模式（Scheme R）：可消模式切换/主屏知识/Y 缩放，但丢失逐屏归一化锚定、副显归属 1 比特仍缺 → "状态换精度"，备查。
  - 免热键自适应：路线 A = 两机 agent 监听 WM_DISPLAYCHANGE 经 vendor HID 推屏幕数（成对事件推导 profile，与二期文本通道共用设施，可作 1.5 期）；路线 B = KVM 按钮线并联/光电贴 LED → GPIO（可选硬件彩蛋）。
  - 推墙手势（贴死+持续单向推进可观测）= v2.x 可选 profile 纠错手势，非自动检测。
  - 固件体积裁剪预案（附录 B）：已作废——余量 ~112KB，无需裁剪；实验脚本存档 backup/size-opt。
